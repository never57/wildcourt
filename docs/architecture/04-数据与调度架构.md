# 04 · 数据与调度架构

> 依据：文档 14（热更结算）、15 §15.3（数据库/Redis）、16（配置表规范）
> 存储：MySQL 13 表 + Redis 8 类 Key；调度：Quartz 4 个 Job

## 4.1 MySQL 表结构（13 表）

| 表名 | 说明 | 核心字段 |
| --- | --- | --- |
| `users` | 用户表 | user_id, nickname, province_id, city_id, level, created_at, last_login |
| `pets` | 宠物表 | pet_id, user_id, type, level, exp, status（在家/派遣中/休息中） |
| `inventories` | 背包表 | user_id, item_id, count（作物/加工产物/非遗/口粮/道具/货币统一入袋） |
| `yards` | 庭院表 | user_id, layout_json, level, updated_at |
| `letters` | 信件表 | letter_id, from_user, to_user, content, item_id, status（撰写中/待审核/通过/退回/送达）, created_at |
| `friends` | 好友关系表 | user_id, friend_id, created_at |
| `nonfiction_collections` | 图鉴收集表 | user_id, province_id, unlocked_at（仅「收到异地玩家赠送」解锁） |
| `badges` | 徽章表 | user_id, province_id, count, first_obtained |
| `transactions` | 交易记录表 | trans_id, user_id, type（shop/minigame/...）, item_id, count, price |
| `match_pools` | 匹配池缓存表 | province_id, user_id, hospitality_score（DB 兜底，热路径走 Redis） |
| `operation_logs` | 操作日志表 | log_id, user_id, action, details, created_at（LogMiddleware 写入） |
| `daily_settlements` | 每日结算队列 | user_id, settle_date, status（待结算/已结算/失败待补） |
| `sign_in_records` | 签到记录表 | user_id, sign_date, cycle_day, reward_shell |

**关键约束与索引建议：**

- `users.province_id`/`city_id`：外键到配置表数据（文档 02 的 34 省 + 300~400 城市）；省份仅身份/派遣目的地，不参与数值。
- `letters`：`from_user`/`to_user` 建索引；`status` 建索引（审核队列扫描）。
- `friends`：`(user_id, friend_id)` 唯一；好友上限 20→100（文档 08 §8.6）。
- `inventories`：`(user_id, item_id)` 唯一；并发扣减用行锁/事务保证不超卖。
- `transactions`：`(user_id, type, created_at)` 索引，支撑防作弊审计与小游戏每日上限核对。
- `daily_settlements`：`(settle_date, status)` 索引，支撑宕机补跑与个别补算。

## 4.2 Redis Key（8 类）

| Key | 类型 | 说明 | 生命周期 |
| --- | --- | --- | --- |
| `user_session:{token}` | String | 用户会话（登录签发，AuthMiddleware 校验） | 随 token 过期 |
| `online_status:{userId}` | String | 在线状态（好友可见性、匹配过滤离线） | 会话期间 |
| `hospitality_values:{provinceId}` | Sorted Set | 好客值排名（member=userId, score=好客值） | 持久维护 |
| `match_pool:{provinceId}` | Sorted Set | 省级匹配池（按好客值排序，`MatchPoolRefreshJob` 重建） | 周期刷新 |
| `match_pool:{provinceId}:{cityId}` | Sorted Set | 城市级匹配池 | 周期刷新 |
| `daily_settlement_queue` | List | 每日结算队列（`DailySettlementJob` 消费） | 结算窗口 |
| `letter_audit_queue` | List | 信件审核队列（`LetterAuditJob` 消费） | 随审核完成 |
| `yard_layout:{userId}` | String | 庭院布局缓存（读多写少） | 随布局变更失效 |

**匹配读路径（文档 07 §7.7）：** `MatchMaker.FindTargets(provinceId, cityId, count, hospitalityValues)` → 先取城市池 `ZRevRange`，不足回退省池，再过滤不可用（离线/食物盆空/被屏蔽），不足用 NPC 庭院补位。

## 4.3 每日结算（DailySettlementJob · 每日 04:00 UTC+8）

| 序号 | 内容 | 说明 |
| --- | --- | --- |
| 1 | 作物成熟判定 | 成熟作物标记可收获（无枯萎惩罚，地块浮动提示） |
| 2 | 口粮品质记录 | 品质于制作时写入，无需每日重算 |
| 3 | 宠物状态恢复 | 派遣中→休息中（归家）；休息满 2h → 在家 |
| 4 | 信件回赠 | 实时送达收件人邮箱（已取消次日批次结算） |
| 5 | 好客值衰减 | 连续未招待 -10/天；空盆 -24h -50；7 日未登录 -100 |
| 6 | 连续招待天数 | 昨日有招待 +1，否则清零 |
| 7 | 每日任务刷新 | 清空旧任务，生成新任务 |
| 8 | 登录奖励发放 | 连续登录 +1，发放对应奖励 |
| 9 | 排行榜更新 | 好客值排行榜重排 |
| 10 | 活动状态检查 | 检查活动开始/结束条件 |

**结算通知（04:00 推送）：**
「早安！你的院子里有[数量]个作物成熟了，食物盆还剩[数量]份食物，[宠物名]已经休息好了在家等你～」

**失败处理：**

| 场景 | 处理 |
| --- | --- |
| 服务器宕机 | 恢复后补跑结算，补偿玩家损失 |
| 个别玩家结算失败 | 记录日志，下次登录时手动补算（`SettlementService.RecoverPlayerAsync`） |
| 时区问题 | 统一服务器时区 UTC+8 |

## 4.4 Job 调度总览

| Job | 触发 | 数据落点 |
| --- | --- | --- |
| `DailySettlementJob` | 每日 04:00 UTC+8 | 读 `daily_settlement_queue` → 写 users/pets/yards/inventories/transactions |
| `MatchPoolRefreshJob` | 周期（如 30min） | `hospitality_values:*` → 重建 `match_pool:*` |
| `ActivityEndJob` | 活动结束时刻 | 关闭活动、补发未领奖励（Lua 配置驱动） |
| `LetterAuditJob` | 消费 `letter_audit_queue` | `AuditService` 三层审核 → 更新 letters.status |

## 4.5 数据一致性要点

1. **货币/物品扣减**：`transactions` 先行记账 + 行锁扣减 `inventories`，失败回滚；所有发放留痕便于对账。
2. **每日结算幂等**：`daily_settlements(settle_date, status)` 唯一约束，同一玩家同一天不重复结算；宕机补跑依赖状态扫描。
3. **Redis 与 MySQL 兜底**：匹配池/排行榜以 Redis 为热路径，`match_pools` 表兜底可重建；好客值以 DB 为权威，Redis 为缓存。
4. **异步队列**：信件审核、结算走 List 队列解耦，Job 消费失败重试（记录日志 + 状态机允许重入）。
5. **时间边界**：所有跨天/结算边界判断统一走 `TimeUtil`（UTC+8），避免客户端时区差异导致双算。
