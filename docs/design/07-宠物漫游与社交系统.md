# 文档七：宠物漫游与社交系统

> 版本：V0.1.0-alpha

## 7.1 宠物属性表

| 属性 | 说明 | 初始值 | 上限 |
| --- | --- | --- | --- |
| 等级 | 决定单次派遣访问数量 | 1 | 20 |
| 经验值 | 升级所需 | 0 | 按等级曲线 |
| 状态 | 在家/派遣中/休息中 | 在家 | - |
| 外观 | 皮肤/装饰 | 默认 | 可更换 |

## 7.2 宠物等级与访问数量

| 等级 | 访问庭院数 | 升级方式 |
| --- | --- | --- |
| 1 | 2 | 初始 |
| 2 | 2 | 喂食/派遣归来 |
| 3 | 3 | 喂食/派遣归来 |
| 5 | 3 | 喂食/派遣归来 |
| 10 | 4 | 喂食/派遣归来 |
| 15 | 5 | 喂食/派遣归来 |
| 20（满） | 5 | 喂食/派遣归来 |

公式：访问数 = floor((等级+2)/5) + 2，上限5

## 7.3 宠物经验获取途径

| 途径 | 经验值 | 说明 |
| --- | --- | --- |
| 派遣归来（每次） | 10 | 基础经验 |
| 成功留下信+非遗 | +5/次 | 有食物时才获得 |
| 被喂食（好友） | +2/次 | 上限+10/天 |
| 每日任务 | 5~20 | 视任务难度 |
| 喂食（自己喂） | +1/次 | 上限+5/天 |

## 7.4 宠物状态流转

```
在家（可互动/可派遣）
    │
    │ 点击"派遣"→选择目的地→确认
    ▼
派遣中（不可互动，显示"外出中"）
    │
    │ 一般次日 04:00 自动归家
    ▼
休息中（不可派遣，显示"疲惫中"）
    │
    │ 休息 2 小时后自动触发
    ▼
在家（可互动/可派遣）
```

## 7.5 派遣流程详细步骤

| 步骤 | 界面 | 交互 | 校验 |
| --- | --- | --- | --- |
| 1 | 点击宠物 | 弹出宠物面板 | 状态必须为"在家" |
| 2 | 点击"派遣" | 弹出手绘地图 | - |
| 3 | 选择省份 | 点击地图省份→弹出城市列表 | 不可选本省 |
| 4 | 选择城市 | 点击城市或"随机" | 可选，不选则随机 |
| 5 | 返回派遣面板 | 确认目的地显示 | - |
| 6 | 选择非遗 | 从背包选择1个非遗 | 必须有≥1个非遗 |
| 7 | 检查口粮 | 自动检查背包 | 必须有≥1份口粮（路上吃） |
| 8 | 写信 | 手写/模板/快捷短语 | 50字限制 |
| 9 | 确认派遣 | 点击"出发" | 全部条件满足才可点击 |

## 7.6 访问触发链（核心逻辑）

```
宠物到达目标庭院
    │
    ▼
Step 1：检查对方食物盆是否有食物
    │
    ├──【无食物】
    │  ① 不留下任何东西
    │  ② 对方收到通知："有只来自[省份]的[宠物名]来过，但你没准备吃的，它饿着肚子走了😢"
    │  ③ 宠物获得1枚该省徽章
    │  ④ 宠物消耗1份自身背包口粮（路上吃）
    │  ⑤ 进入下一个庭院（如果有）
    │
    └──【有食物】
        ① 宠物吃掉对方食物盆里的1份口粮，并按该份口粮的结算品质触发吐槽台词（详见文档五 5.8）
        ② 宠物消耗1份自身背包口粮（路上吃）
        ③ 留下1封信（存入对方信箱）
        ④ 留下1个非遗（存入对方信箱）
        ⑤ 对方收到通知："有只来自[省份]的[宠物名]留下了信件和[非遗物件名称]🎁"
        ⑥ 宠物获得1枚该省徽章
        ⑦ 进入下一个庭院（如果有）
```

## 7.7 匹配算法（Lua实现）

```lua
function MatchMaker.FindTargets(provinceId, cityId, count, hospitalityValues)
    -- provinceId: 目标省份
    -- cityId: 目标城市（nil则不限城市）
    -- count: 需要匹配的庭院数量
    -- hospitalityValues: 该省份的好客值Sorted Set

    local candidates = {}

    if cityId then
        -- 指定城市：先从该城市的好客值池取
        candidates = Redis.ZRevRange("match_pool:"..provinceId..":"..cityId, 0, count*3)
    end

    -- 城市不够或从省池补充
    if #candidates < count then
        local provinceCands = Redis.ZRevRange("match_pool:"..provinceId, 0, count*3)
        for _, c in ipairs(provinceCands) do
            if not in_list(candidates, c) then
                table.insert(candidates, c)
            end
        end
    end

    -- 过滤不可用（离线/食物盆空/被屏蔽）
    local targets = {}
    for i, userId in ipairs(candidates) do
        if CheckUserAvailable(userId) then
            table.insert(targets, userId)
            if #targets >= count then break end
        end
    end

    -- 不足时填充NPC庭院
    while #targets < count do
        table.insert(targets, GetNPCCourtyard(provinceId))
    end

    return targets
end
```

## 7.8 匹配权重说明

| 权重因素 | 说明 | 占比 |
| --- | --- | --- |
| 好客值 | 主要排序依据 | 60% |
| 随机扰动 | 防止马太效应 | 20% |
| 首次访问优先 | 未访问过的庭院优先 | 10% |
| 好友权重 | 好友庭院权重略高 | 10% |

## 7.11 玩家等级系统（独立于宠物等级）

玩家等级由经验值（EXP）驱动，详见文档三 3.5，与本章 7.1~7.3 的**宠物等级系统完全独立**，互不影响：

| 维度 | 玩家等级 | 宠物等级 |
| --- | --- | --- |
| 经验来源 | 种地/加工/制作非遗/派遣/签到/小游戏/收信/互访/新手引导 | 派遣归来/留信/被喂食/每日任务/自喂 |
| 等级上限 | 4级（对应庭院解锁进度） | 20级（决定单次派遣可访问庭院数） |
| 配置表 | Config_PlayerLevel（文档十六 Sheet17） | 宠物等级曲线（文档十六宠物相关表） |
| 客户端脚本 | Scripts/PlayerLevel.cs | 宠物相关脚本 |
| 服务端 | PlayerService.cs | PetService.cs |

玩家等级只决定庭院容量（农田/槽位/装饰上限等），宠物等级只决定单次派遣可访问的庭院数量，二者解耦。

## 7.12 非遗流通与展示柜货源闭环

展示柜仅接受"他人给予"的非遗，自制物品不可入柜（见文档六）。一条非遗能否入柜，由它的 `来源标签` 决定，与玩家最初如何获得它无关。三类可入柜来源及生成链路：

| 来源标签 | 产生方式 | 归属方 | 是否可入柜 |
| --- | --- | --- | --- |
| 拜访留下 | 派遣宠物访问**有食物**的庭院时，自动把随行的 1 个非遗存入**被访问方**信箱 | 被访问方 | 是（展示柜主货源） |
| 回赠 | 被访问方读信后点"回赠"，自选背包 1 个非遗+写信寄回**原发信人** | 原发信人 | 是 |
| 回访所得 | 双方加好友后互访，接待方当场赠出 1 个非遗给来访者 | 来访者 | 是 |
| 自制 | 工坊制作产出，直接进自己背包 | 制作者本人 | 否 |

关键流向澄清：

1. 派遣时玩家从背包选 1 个非遗随行（随行物来源不限：可为自制/已有/曾收到的回赠等）；访问有食物的庭院后，该非遗留在**对方**信箱——即"拜访留下"，归被访问方所有，可入其展示柜。
2. "回赠"是单向回应：收信方（被访问方）把非遗回寄给**最初派遣宠物的玩家（原发信人）**，而非无差别群发。
3. "回访所得"依赖好友关系，是互访时的主动赠予，与自动的"拜访留下"区分。
4. 展示柜货源完全来自上述三类他人给予；结合"自制不可入柜"，玩家可无限自制→派遣消耗→图鉴永久点亮，但自家展示柜只能靠社交往来填充。
